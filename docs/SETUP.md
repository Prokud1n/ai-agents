# Установка и проверка M0

Пошаговая установка с нуля на macOS (Docker Desktop) и на Linux-VPS, справочник переменных `.env`
и сквозная проверка `make m0-check`, которая за один проход проверяет все «кирпичи»: стек, LLM, базу знаний,
транскрипцию и Telegram Bot API.

## 1. Требования

| Что | Зачем | Версия |
|---|---|---|
| Docker | весь стек работает в контейнерах | Docker Desktop (macOS) или Docker Engine (Linux) |
| Docker Compose v2 | `docker compose …` (через пробел; старый `docker-compose` v1 не подходит) | v2.20+ (`--wait`) |
| make, git, curl | команды проекта, клонирование, проверка `/readyz` | любые актуальные |
| Go | только для разработки (`make check`), `make transcribe` / `make roughcut` / `make subtitles` на хосте и `KB_HOST=1 make kb-*` | 1.21+; нужную версию (1.26 из `go.mod`) Go скачает сам, если не задан `GOTOOLCHAIN=local` |
| ffmpeg, ffprobe | только `make transcribe`, `make roughcut` и `make subtitles` на хосте (для субтитров — сборка с libass, фильтр `ass`); без них все три работают в образе `media` | 8.x |

Без Go работает всё, что нужно оператору: стек, агенты (`make agent-run`), база знаний (`make kb-*` запускают `kb`
в образе приложения), транскрипция и субтитры в образе `media`.

### macOS

1. Установи [Docker Desktop](https://docs.docker.com/desktop/setup/install/mac-install/) и запусти его
   (иконка кита в строке меню должна перестать «крутиться»). Compose v2 и `docker compose` входят в комплект.
2. В Docker Desktop → Settings → Resources дай не меньше 4 ГБ памяти: сборка образа и pgvector.
3. `make`, `git`, `curl` — из Xcode Command Line Tools: `xcode-select --install`.
4. Go и ffmpeg (по желанию, для разработки): `brew install go ffmpeg` ([Homebrew](https://brew.sh)) или установщик с
   [go.dev/dl](https://go.dev/dl/).

### Linux-VPS (Ubuntu/Debian)

1. Docker Engine и плагин compose — по [официальной инструкции](https://docs.docker.com/engine/install/)
   (пакеты `docker-ce` и `docker-compose-plugin` из репозитория Docker, не `docker.io` из дистрибутива — в нём часто
   нет compose v2).
2. Чтобы запускать docker без sudo: `sudo usermod -aG docker "$USER"`, затем перелогиниться
   ([post-install](https://docs.docker.com/engine/install/linux-postinstall/)).
3. `sudo apt-get install -y make git curl`; Go — с [go.dev/dl](https://go.dev/dl/) (в apt обычно старый), ffmpeg —
   `sudo apt-get install -y ffmpeg` (по желанию).
4. Наружу стек публикует только `app` и `postgres`, и только на `127.0.0.1`, поэтому файрвол для них открывать не нужно.
   Для доступа к Postgres с ноутбука используй SSH-туннель: `ssh -L 5432:127.0.0.1:5432 user@vps`.

Проверка: `docker compose version`, `docker info` (без ошибки), `make --version`, `go version` (если нужен).

## 2. Клонирование и `.env`

```bash
git clone https://github.com/Prokud1n/ai-agents.git
cd ai-agents
cp .env.dist .env
```

`.env` в `.gitignore`: ключи и пароли в git не попадают. Значения из `.env.dist` годятся для локальной разработки как
есть; ключи API добавляются по мере надобности (раздел 4). Для продакшна обязательно смени пароли (ниже).

После обновления репозитория сравни `.env` с `.env.dist`: новые переменные в `.env` сами не появятся
(`make m0-check` покажет, каких не хватает).

## 3. Справочник переменных `.env`

«Секрет» — значение нельзя коммитить, показывать в скриншотах и логах. «Обязательна» — без неё не стартует стек
или соответствующая функция; остальные можно не трогать. Колонка «В `.env.dist`» — значение из шаблона, с которым
работает `cp .env.dist .env`. Если переменную из `.env` удалить, код возьмёт свой дефолт, и он бывает другим
(например, `POSTGRES_HOST=localhost`, `TELEGRAM_FILES_DIR=/var/lib/telegram-bot-api`), поэтому лучше не удалять,
а менять значение.

Формат `.env`: `KEY=VALUE`, по строке на переменную. Кавычки допустимы для `make` и `docker compose`, но
`docker run --env-file` (ручной запуск образа `media` из README) их не снимает: для него пиши значения без кавычек.
`make m0-check` передаёт переменные в `docker run` сам, кавычки ему не мешают.
`make m0-check` читает `.env` построчно и не раскрывает в нём `${VAR}`, `~` и `\"`, поэтому пути (например, `KB_ROOT`)
пиши явно: `KB_ROOT=./kb`, а не `KB_ROOT=~/kb` или `${HOME}/kb`.

> **Продакшн.** Обязательно смени `POSTGRES_PASSWORD`, `REDIS_PASSWORD`, `S3_ACCESS_KEY` и `S3_SECRET_KEY`: значения
> из `.env.dist` публичны. Сгенерировать: `openssl rand -base64 32 | tr -d '/+='`. Пароль Postgres задаётся только
> при первом создании тома, поэтому меняй его до первого `make up` (или см. «Типовые проблемы»).

## 4. Где получить ключи

Все ключи — только на официальных сайтах. Ключ показывается один раз: сразу вставь его в `.env`.
Не присылай ключи в чаты и не прикладывай `.env` к отчётам: `make m0-check` печатает только «задан (…последние 4 символа)».

- **Claude API (`ANTHROPIC_API_KEY`).** [Claude Console](https://platform.claude.com/docs/en/get-api-key) → войти →
  Settings → API keys → Create Key. Нужны пополненный баланс (Settings → Billing) или кредиты по подписке (ниже)

## 5. Материалы базы знаний (`KB_ROOT`)

`kb ingest` берёт файлы только из папки `./kb` проекта. Папка в `.gitignore` и `.dockerignore`: материалы
тренера не попадают ни в git, ни в образ. `source` документа — путь относительно неё (например, `brand/voice.md`).

`make kb-*` запускают CLI `kb` из образа приложения (`docker compose run --rm --entrypoint /app/kb app …`,
`scripts/kb.sh`), Go на хосте не нужен. Нужен поднятый стек (`make up`): база — сервис `postgres`, образ — тот, что
собрал `make up`. Без образа или без запущенного `postgres` команда сразу останавливается с подсказкой `make up`;
если `cmd/`, `internal/`, `go.mod`, `go.sum` или `Dockerfile` менялись после сборки образа (например, после
`git pull`), печатается предупреждение «образ старше кода» — тоже `make up`. Запрос, начинающийся с `-`, работает:
`make kb-search Q="-5 кг"`.
`./kb` монтируется в контейнер только на чтение в `/kb`, там `KB_ROOT=/kb`. `KB_PATH` пишется как на хосте
(`./kb/brand`, `kb/brand` или абсолютный путь) и переводится в `/kb/brand`; путь вне `./kb` — ошибка
«вне папки базы знаний». Симлинки, ведущие из `./kb` наружу, в контейнере не читаются.

Права. Контейнер работает не от root: с uid:gid пользователя хоста, поэтому читает всё, что может прочитать сам
пользователь, в том числе файлы с правами `600`. Если команды запускаются от root хоста, `kb` остаётся непривилегированным
пользователем образа (uid 65532): тогда файлам нужны права на чтение для всех (`644`, папкам — `755`):
`chmod -R a+rX kb`. На macOS (Docker Desktop) права обычных файлов отдельно настраивать не нужно. С rootless Docker
и Podman uid хоста внутри контейнера сдвигается (user namespace), поэтому файлам тоже нужны права `644`, папкам — `755`.

Для разработчиков: `KB_HOST=1 make kb-…` запускает `go run ./cmd/kb` на хосте, как раньше: `KB_ROOT` из `.env`,
Postgres — на `127.0.0.1:POSTGRES_HOST_PORT`.

Форматы: `.md`, `.txt`, `.docx`, `.pdf` (только текстовый слой: сканы сначала распознать). Файл до 32 МБ, до
1 000 000 символов. Скрытые файлы и папки (`.…`) пропускаются. Заголовок `# …` в начале файла становится названием.

Рекомендуемая структура — по `kind` (тип задаётся при загрузке и используется как фильтр поиска):

```
kb/
  brand/     # kind=brand: голос бренда, ЦА, ценности, брендбук, табу, примеры формулировок
  product/   # kind=product: программы тренировок, марафоны, консультации, цены, условия
  post/      # kind=post: лучшие посты и сценарии Reels — образцы стиля
  other/     # kind=other: всё остальное (FAQ, биография, кейсы клиентов)
```

```bash
make up
make kb-ingest KB_PATH=./kb/brand KB_KIND=brand
make kb-ingest KB_PATH=./kb/product KB_KIND=product
make kb-ingest KB_PATH=./kb/post KB_KIND=post
make kb-search Q="как мы говорим о питании" LIMIT=5
```

Агент ищет по загруженным материалам, если в `tools:` его `agent.md` есть `search_knowledge_base` (пример — шаблон
`agents/_example/`, подробности — README, «Доступ агента к базе знаний»):

```bash
cp -r agents/_example agents/test && sed -i 's/^name: _example$/name: test/' agents/test/agent.md
make agent-run AGENT=test PROMPT="Напиши короткий пост о том, как мы говорим о питании"
```

Без `KB_KIND` у уже загруженного документа сохраняется его тип (у нового — `other`); сменить тип можно только
с `KB_FORCE=1`. Один документ — одна тема: так поиск точнее. Временные папки `kb/_m0check.XXXXXX/` создаёт и удаляет
`make m0-check`, не клади туда свои файлы.

## 6. Запуск, проверка, остановка

```bash
make up                              # собрать образ, применить миграции (сервис migrate), поднять всё и дождаться healthy
curl 127.0.0.1:8080/readyz           # {"status":"ok","dependencies":{"postgres":"ok","redis":"ok","s3":"ok","telegram":"ok"}}
docker compose ps                    # app, postgres, redis, s3 — healthy; migrate — Exited (0)
make logs                            # логи всех сервисов (Ctrl+C — выйти)
```

Миграции применяются автоматически при каждом `make up`. Вручную: `make migrate` (все новые), `make migrate-down`
(откатить одну). Текущая версия:

```bash
docker compose exec postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "SELECT * FROM schema_migrations"'
```

Должна совпадать с номером последнего файла в `migrations/`, `dirty = f`.

Telegram Bot API (по желанию, нужны `TELEGRAM_API_ID`/`TELEGRAM_API_HASH`): `docker compose --profile telegram up -d`.

Остановка и сброс:

```bash
make down                            # остановить; данные (тома postgres, redis, s3, bot api) сохраняются
docker compose --profile telegram down -v   # остановить и УДАЛИТЬ все данные: базу, загруженные медиа, базу знаний
```

`down -v` необратим: перед ним сделай дамп, если данные нужны
(`docker compose exec postgres sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > dump.sql`).

### Telegram-боты (шлюз)

Один сервис `app` ведёт четырёх ботов-«сотрудников» через локальный Bot API: тренер пишет в супергруппу с топиками,
шлюз принимает текст, голосовые, аудио, видео, видеокружки, видео-документы и фото, решает, какому агенту адресовано
сообщение, и отвечает от его бота. Сообщение становится задачей агента этой роли, а черновик с кнопками приходит в тот
же топик (`internal/teamchat`, сценарий — «Ручная проверка M1» ниже).

**Как боты получают сообщения.** Все сообщения группы получает только Маркетолог («диспетчер»): у него выключен
privacy mode. Остальные боты запрашивают у Telegram только нажатия своих кнопок (`callback_query` всегда приходит
боту, чьё сообщение с кнопкой), поэтому одно сообщение никогда не обрабатывается дважды. Сверху — защита от повторов:
каждое событие помечается в Redis до обработки (если обработчик вернул ошибку или упал, метка снимается), а `offset`
каждого бота сохраняется в Redis после каждого обновления, так что после рестарта старые сообщения не обрабатываются
снова. Если процесс упадёт посреди обработки, это сообщение придётся отправить заново. Нажатия кнопок обрабатываются
в отдельном пуле и не ждут скачивания видео; нажатие чужого пользователя получает пустой ответ (чтобы не крутился
индикатор), а если обработчик упал — шлюз сам отвечает на нажатие без текста.

Каждый бот подключается независимо. Если Telegram отклонил токен (401), бот останавливается до рестарта, в логе —
одна ошибка с именем переменной, а `/readyz` показывает `"telegram":"fail"`; остальные боты работают. Временная
недоступность Bot API на `/readyz` не влияет: шлюз повторяет запросы. Запросы с токеном идут только на
`TELEGRAM_BOT_API_URL`: без прокси из окружения и без редиректов.

**Кому адресовано сообщение** (по порядку):

1. явное `@упоминание` бота — его роль; команда `/plan@имя_бота` — роль этого бота;
2. ответ (reply) на сообщение бота — роль этого бота;
3. команды `/plan`, `/idea`, `/status`, `/pause` без имени бота — Маркетолог;
4. иначе по топику: «Исходники» → Монтажёр, «Планёрка», «Продакшн», «Техничка» и всё прочее → Маркетолог.

Сообщения из других чатов, от пользователей не из `TELEGRAM_ALLOWED_USER_IDS`, от имени группы или канала (анонимный
админ, `sender_chat`), от ботов и личные сообщения ботам молча игнорируются (в логе — `debug` без содержимого). Пиши
в группу от своего имени. Картинка, отправленная файлом (`image/*`), приходит как фото — для Дизайнера. Документы,
кроме видео и картинок, и стикеры шлюз пока не принимает; альбом приходит отдельными сообщениями, по одному на файл.
Пересланные сообщения помечаются `Forwarded`: агенты считают их текст данными, а не инструкцией.

**Контракт обработчика (`gateway.Handler`).** Он должен быть быстрым и идемпотентным: записать задачу (T1.3 делает
это по ключу `chat_id`+`message_id`, для кнопок — по ID нажатия) и вернуться; тяжёлая работа (LLM, монтаж) уходит
в очередь. Одновременно выполняется `TELEGRAM_WORKERS` обработчиков сообщений и столько же — нажатий. Скачанный
файл читается только через `Media.Open()` (путь содержит токен бота и наружу не отдаётся) и сразу копируется к себе,
в S3: Bot API может удалить старые файлы (storage optimizer). Заменить обработчик по умолчанию — `fx.Decorate` (или
`fx.Replace`) для `gateway.Handler`.

**Исходящие файлы.** `gateway.Sender.SendMedia` отправляет только обычные файлы из `TELEGRAM_OUTBOX_DIR` (по умолчанию
`/tmp/telegram-outbox` внутри контейнера `app`; туда кладут результат монтаж и обложки). Шлюз создаёт каталог при
старте с правами 0700 и не стартует, если на этом месте симлинк или файл. Путь вне каталога, через `..` или симлинк
наружу, FIFO и устройства — ошибка. Файлы Bot API (`TELEGRAM_FILES_DIR`) напрямую не отправляются: их пути содержат
токен. Если файлы будет готовить другой контейнер (например, образ `media`), понадобится общий том, смонтированный в
`app` по пути `TELEGRAM_OUTBOX_DIR`, — это для следующих задач.

**Очередь событий.** Цикл опроса не ждёт свободного обработчика: принятое событие встаёт в очередь (до 256 событий)
и ждёт слот в своём пуле, поэтому нажатие кнопки не стоит за скачиванием видео. Опрос остановится, только если
в очереди 256 событий — при одном тренере это недостижимо, а память ограничена. При остановке очередь
дорабатывается в пределах `APP_STOP_TIMEOUT`; если таймаут истёк, метка оставшихся событий снимается, но их offset
уже сохранён, и такие события теряются (их нужно отправить заново). Маркетолог начинает опрос, когда остальные боты подключились (или
отклонены с 401), чтобы на старте `@упоминания` не уходили не тому боту; пока Bot API недоступен, сообщения
ждут в Telegram. Текст длиннее 4096 символов уходит несколькими
сообщениями (кнопки — у последнего), подпись длиннее 1024 — отдельными сообщениями ответом на файл.

**1. Боты в @BotFather** (для каждого из четырёх: `/newbot`, затем):

- Маркетолог: `/setprivacy` → бот → **Disable** (он должен видеть все сообщения группы). Делай это **до**
  добавления бота в группу; если бот уже в группе — удали его и добавь заново, иначе настройка не применится.
- Остальным трём privacy mode не трогай: им сообщения не нужны.
- `/setjoingroups` → **Disable** для всех четырёх после того, как добавишь их в группу: чужие не затащат ботов к себе.
- Если бот раньше работал через облачный `api.telegram.org`, перед переходом на локальный сервер вызови один раз
  `logOut`: `curl -s https://api.telegram.org/bot<токен>/logOut` (команду набирай, не сохраняя в истории shell,
  например с пробелом в начале). Если у бота был вебхук — `deleteWebhook`, иначе `getUpdates` отвечает 409.

**2. Супергруппа.** Создай группу, в настройках включи **Topics** (группа станет супергруппой-форумом), создай топики
«Планёрка», «Исходники», «Продакшн», «Техничка». Добавь четырёх ботов и сделай их **администраторами** с правом
отправлять сообщения (Маркетолога — обязательно, если privacy mode не выключен: админ видит всё). Права на удаление и
бан ботам не нужны.

**3. ID группы, топиков и пользователей.**

- Свой user ID: напиши [@userinfobot](https://t.me/userinfobot) — он ответит числом `Id`. ID тренера — так же, с
  её телефона (или перешли боту её сообщение).
- ID группы и топиков: открой [Telegram Web](https://web.telegram.org/a/), зайди в топик группы. Адрес вида
  `…/#-1001234567890_7`: `-1001234567890` — `TELEGRAM_GROUP_ID`, `7` — ID топика. Так для каждого топика.
  Если в адресе нет `-100`, допиши его: ID супергрупп в Bot API всегда начинаются с `-100`. Другой способ — в
  десктопном клиенте «Копировать ссылку» на сообщение в топике: `https://t.me/c/1234567890/7/15` → группа
  `-1001234567890`, топик `7`.

**4. `.env` и запуск.** Заполни `TELEGRAM_API_ID`/`TELEGRAM_API_HASH` (раздел 4), четыре `TELEGRAM_*_TOKEN`,
`TELEGRAM_GROUP_ID`, `TELEGRAM_ALLOWED_USER_IDS`, `TELEGRAM_TOPIC_*_ID`, затем:

```bash
docker compose --profile telegram up -d --build --wait
docker compose logs -f app | grep 'telegram gateway'   # "bot connected" для каждого из четырёх ботов
```

Шлюз не ждёт Bot API при старте: пока сервер поднимается, `app` пишет `failed to get bot identity, retrying` и
повторяет попытки. Если ошибка не уходит — смотри «Типовые проблемы».

**5. Ручная проверка.**

| Действие в группе | Ожидаемый ответ |
|---|---|
| текст в «Продакшн» | реакция 👀 на сообщение, затем черновик от Маркетолога реплаем, с кнопками |
| текст в «Исходники» | от Монтажёра сразу фиксированный ответ «монтаж пока не подключён», без задачи |
| `@имя_бота_копирайтера напиши подпись` в любом топике | черновик от Копирайтера |
| реплай на сообщение Дизайнера | от Дизайнера фиксированный ответ «обложки пока не подключены», без задачи |
| `/plan неделя` или `/plan@имя_бота_маркетолога` | 👀 и черновик плана от Маркетолога |
| голосовое; видео (в т.ч. больше 20 МБ) в «Исходники» | сразу «Голосовые и видео пока не обрабатываю…» от Монтажёра. Пока медиа не обрабатываются, шлюз файл **не скачивает** (`gateway.MediaFilter`), поэтому ответ не ждёт загрузки; проверка скачивания больших файлов и прав `group_add` (`ls -ln /var/lib/telegram-bot-api/*:*/videos`: `-rw-r-----`, группа `101`) вернётся вместе с приёмом видео |
| картинка файлом (PNG без сжатия) | «Фото и картинки пока не обрабатываю…» |
| сообщение от имени группы (анонимно) | тишина |
| сообщение от аккаунта не из белого списка; личное сообщение боту | тишина |
| `docker compose restart app` после пары сообщений | старые сообщения не получают повторный ответ и не создают задачи снова |

### Ручная проверка M1

Цель M1: тренер пишет в группу → агент присылает черновик с кнопками → одобрить, правка реплаем или отклонить.

**Что настроить.** Всё из «Telegram-боты» выше: четыре бота (у Маркетолога выключен privacy mode), супергруппа с
топиками «Планёрка», «Исходники», «Продакшн», «Техничка», боты — админы. В `.env`: `TELEGRAM_API_ID`,
`TELEGRAM_API_HASH`, четыре `TELEGRAM_*_TOKEN`, `TELEGRAM_GROUP_ID`, `TELEGRAM_ALLOWED_USER_IDS` (ваш ID и ID
тренера), `TELEGRAM_TOPIC_*_ID`; `ANTHROPIC_API_KEY` — агенты пишут черновики через Claude; `OPENAI_API_KEY` —
по желанию: без него агенты пишут без базы знаний (и говорят об этом), правки сохраняются без эмбеддинга.
Запуск: `docker compose --profile telegram up -d --build --wait`; в логе `app` — `bot connected` для четырёх ботов и
`agents: loaded` с `copywriter` и `marketer`.

**Что пока не работает:** голосовые и видео (транскрипция идей и монтаж — E2/E3; файлы пока даже не скачиваются),
фото и обложки, Монтажёр и Дизайнер как агенты, `/pause`,
публикация одобренного (одобрение только фиксирует версию и сохраняет правку тренера в базу знаний), голос бренда
(T2.1) и полноценные скиллы агентов.

## 7. Проверка M0 (`make m0-check`)

Сквозная проверка: что окружение настроено и каждый кирпич работает с реальными ключами. Те же шаги вручную,
по одному — в [M0-MANUAL.md](M0-MANUAL.md).

```bash
make m0-check                        # шаги без ключей — SKIP
make m0-check M0_VIDEO=./clip.mp4    # плюс транскрипция ролика (лучше 10–60 с речи)

# плюс getMe тестового бота через локальный Bot API; токен — только в окружении, не в .env и не в истории shell
read -rs M0_BOT_TOKEN && export M0_BOT_TOKEN && make m0-check; unset M0_BOT_TOKEN
```

> **`M0_BOT_TOKEN` — только для тестового бота.** При первом запросе локальный сервер Bot API логинит бота у себя;
> боту, который в это время работает через облачный `api.telegram.org`, это может помешать (обновления и вебхук
> переходят к локальному серверу). Заведи у @BotFather отдельного бота для проверок. Токен не пишется в `.env`,
> логи и отчёт; ответ `getMe` не сохраняется.

| Шаг | Что проверяет | Когда SKIP |
|---|---|---|
| 1. Окружение | docker, compose v2, daemon, make, curl, `.env`; обязательные переменные заданы; WARN — dev-пароли, переменные из `.env.dist`, которых нет в `.env`, и отсутствие git (в отчёте `Git: unknown`) | никогда |
| 2. Стек | `make up`, все сервисы healthy, `/readyz` = ok по всем зависимостям, версия миграций = последней в `migrations/`, не dirty | шаг 1 не прошёл |
| 3. LLM | временная копия `agents/_example` в `agents/m0check-<pid>`, `make agent-run PROMPT="Ответь одним словом: работает"`: ответ не пустой, есть строка расхода | нет `ANTHROPIC_API_KEY` |
| 4. База знаний | документ `m0-check-<pid>-<время>.md` во временной `kb/_m0check.XXXXXX/`; проверка, что такого source в базе нет; `make kb-ingest`, `make kb-search` по фразе из него (в образе приложения) — документ первый, `make kb-delete` | нет `OPENAI_API_KEY` (или `KB_HOST=1` без Go) |
| 5. Транскрипция | `make transcribe` на `M0_VIDEO` (без Go/ffmpeg на хосте — в образе `media`): JSON с непустым `language` и `words` | нет ключа или `M0_VIDEO` |
| 6. Telegram | поднимает `telegram-bot-api` и ждёт его healthcheck: PASS «порт открыт, ключи не проверены». С `M0_BOT_TOKEN` — ещё `getMe` через локальный сервер, это проверяет `api_id`/`api_hash` и токен. Если сервис был остановлен — останавливает обратно | нет `TELEGRAM_API_ID`/`TELEGRAM_API_HASH` |

В конце — таблица PASS / FAIL / SKIP; код выхода не 0, если есть хоть один FAIL. Всё сохраняется в `m0-results/`
(в `.gitignore`):

- `report.md` — **приложи его к отчёту**: дата, git SHA, шаги с длительностью, предупреждения, расход LLM из
  `llm_usage` за прогон, версии образов. Секретов в нём нет;
- `up.log`, `llm.out`/`llm.log`, `kb.log`, `transcribe.log`, `telegram.log` — подробности для FAIL. Ключи
  (`sk-…`, токены ботов, значения ключей и паролей из `.env`) в них маскируются, но логи — для разбора на месте:
  **не пересылай их** и не прикладывай к отчёту, там могут быть адреса, тексты и прочие внутренние детали;
- `transcript.json` — результат транскрипции (содержит текст ролика).

Скрипт можно запускать повторно. Он не трогает пользовательские данные и удаляет только то, что создал сам:
временный агент `agents/m0check-<pid>`, папку `kb/_m0check.XXXXXX` и документ в базе знаний с уникальным
именем. Если такой путь или документ уже есть — шаг FAIL, чужое не трогается. `.env` читается построчно и не
исполняется. Ctrl+C прерывает весь прогон (код 130) и убирает временное; `down -v` скрипт не делает. Стоимость прогона с ключами — доли цента (один короткий запрос
к Claude, эмбеддинги двух коротких текстов) плюс Whisper по длине ролика.

Ограничение шага 6 без `M0_BOT_TOKEN`: у Bot API нет health-эндпоинта, healthcheck проверяет только, что порт 8081
принимает соединения. Неверные `api_id`/`api_hash` видны в `docker compose --profile telegram logs telegram-bot-api`
или при проверке с токеном тестового бота.

## 8. Типовые проблемы

| Симптом | Причина и решение |
|---|---|
| `Cannot connect to the Docker daemon` | Docker Desktop не запущен (macOS) или нет прав (Linux: группа `docker`, перелогиниться) |
| `docker: 'compose' is not a docker command` | стоит compose v1 или нет плагина: установи `docker-compose-plugin` (Linux) / обнови Docker Desktop |
| `POSTGRES_PASSWORD is required` (и т.п.) при `make up` | нет `.env` или в нём пустая переменная: `cp .env.dist .env` |
| `bind: address already in use` на 8080 или 5432 | порт занят (свой Postgres, другой проект): задай `APP_HOST_PORT` / `POSTGRES_HOST_PORT` в `.env` |
| `make up` висит, `app` unhealthy | `docker compose logs app migrate`; чаще всего неверные пароли или упавшая миграция |
| `password authentication failed` после смены `POSTGRES_PASSWORD` | пароль применяется только при первом создании тома. Смени его в самой базе (внутри контейнера вход по сокету без пароля): `docker compose exec postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "\password $POSTGRES_USER"'` — новый пароль спросит интерактивно, он должен совпасть с `.env`; затем `make up`. Если данные не нужны — `docker compose down -v` |
| `app` не проходит проверку S3 после смены `S3_ACCESS_KEY`/`S3_SECRET_KEY` | ключи — учётка администратора RustFS. На свежей установке проще всего `down -v`; на рабочей — меняй ключи до первого запуска |
| `/readyz` = 503 | в JSON видно, какая зависимость `fail`; причина — в `docker compose logs app` |
| `migrate` упал, база `dirty` | `docker compose logs migrate`; исправь миграцию (если она не смержена) и повтори `make migrate`. Смерженные миграции не редактируются |
| `anthropic api key is not set` | пустой `ANTHROPIC_API_KEY` в `.env` |
| Claude: `401` / `invalid x-api-key` | ключ неверный или отозван: создай новый в Console |
| Claude: `credit balance is too low` | на балансе организации Console нет денег и кредитов: пополни Billing или привяжи подписку (раздел 4) |
| OpenAI: `401` / `invalid_api_key` | ключ неверный или отозван |
| OpenAI: `insufficient_quota` | на балансе OpenAI нет денег (Billing на platform.openai.com) |
| `make kb-*`: `failed to connect` / `connection refused` к `postgres` | стек не поднят: `make up` |
| `make kb-*`: «образ … не собран», «стек не поднят» или `exec: "/app/kb": no such file or directory` | образа нет, он собран до появления `kb` или стек остановлен: `make up` |
| `make kb-*`: «образ … старше кода» | код обновился после сборки образа: `make up` |
| `make kb-ingest`: «вне папки базы знаний» | `KB_PATH` должен указывать внутрь `./kb`: положи материалы туда |
| `make kb-ingest`: `permission denied` | команды запущены от root, а файлы в `./kb` недоступны другим: `chmod -R a+rX kb` (раздел 5) |
| `KB_HOST=1 make kb-*`: `connection refused` к `127.0.0.1:5432` | стек не поднят (`make up`) или `POSTGRES_HOST_PORT` отличается от того, с которым поднят стек |
| `make transcribe`: `"ffmpeg": executable file not found` | установи ffmpeg или используй образ `media` (README, «Транскрипция видео») |
| `make roughcut`: `invalid plan` | в `plan.json`, переданном через `-plan`, интервалы `keep` должны идти по возрастанию, не пересекаться, не выходить за длину видео, быть не короче кадра и не больше 500 штук; `version` — 1. Больше 500 кусков в автоматическом плане — подними `-max-pause` (README, «Черновая склейка») |
| `make roughcut`: `source has no audio stream` | ролик без звука не поддерживается: склейка идёт по речи |
| `make roughcut`: `invalid rough cut settings` | `ROUGHCUT_MAX_PAUSE` должна быть больше 0, `ROUGHCUT_RETAKE_SIMILARITY` — в пределах (0, 1] |
| Транскрипция режет речь посреди фраз, видео с музыкой | подними `TRANSCRIPTION_SILENCE_NOISE_DB` до `-25` |
| `make subtitles`: `No such filter: 'ass'` | ffmpeg собран без libass: поставь полную сборку (`brew install ffmpeg`, `apt-get install ffmpeg`) или используй образ `media` |
| `subtitles`: код выхода 2, «brand fonts were not found» | в `SUBTITLES_FONTS_DIR` нет файла шрифта из стиля или имя в стиле не совпадает с тем, что ищет libass (для Medium/ExtraBold — «Manrope Medium», последнее имя в `fc-scan`); вариативный шрифт замени статическим (README, «Субтитры») |
| Apple Silicon: сборка медленная | первый `make up` собирает образ (несколько минут); дальше работает кэш |
| `m0-check`: шаг 4 FAIL «не первый в поиске» | в базе есть очень похожий документ или сменилась модель эмбеддингов без `make kb-reembed`; подробности — `m0-results/kb.log` |
| `m0-check`: шаг 6 FAIL «getMe не ok» | неверный `M0_BOT_TOKEN` или `TELEGRAM_API_ID`/`TELEGRAM_API_HASH`; смотри `docker compose --profile telegram logs telegram-bot-api` |
| `docker run --env-file .env`: ключ «неверный», хотя в `.env` он правильный | `--env-file` не снимает кавычки: убери кавычки вокруг значений в `.env` |
| `invalid telegram gateway config` при старте `app` | задан хотя бы один `TELEGRAM_*_TOKEN`, но не все четыре, нет `TELEGRAM_GROUP_ID` или пуст `TELEGRAM_ALLOWED_USER_IDS`; в ошибке названы переменные |
| `telegram gateway: failed to get bot identity, retrying` не прекращается | Bot API не запущен (`docker compose --profile telegram up -d`) или неверные `TELEGRAM_API_ID`/`TELEGRAM_API_HASH` (логи `telegram-bot-api`) |
| `failed to get updates` с `409 Conflict` | этого бота поллит ещё кто-то (вторая копия `app`, старый скрипт) или у бота вебхук: останови лишнее, вызови `deleteWebhook` |
| На сообщение не появляется 👀, хотя черновик приходит | в группе ограничены реакции (настройки группы → Реакции): это только предупреждение `failed to react to the task message` в логе, на работу не влияет. Разреши 👀 или все реакции, если отметка нужна |
| Бот не отвечает на обычные сообщения, а на `@упоминания` отвечает | у Маркетолога не выключен privacy mode: `/setprivacy` → Disable, затем удалить и снова добавить его в группу (или сделать админом) |
| «Не смог скачать файл» на видео; в логе `rejected file path` | `permission denied` — `app` не может читать файлы `telegram-bot-api`: сервер создаёт медиа с правами 0640 и группой 101, а `app` получает эту группу через `group_add: ["101"]` в `docker-compose.yml` (проверь `ls -ln`, раздел 6); `file path is not absolute` — `TELEGRAM_BOT_API_URL` указывает на публичный API, а не на локальный сервер |
| `/readyz`: `"telegram":"fail"`; в логе `bot token rejected` | Telegram отклонил токен бота из `variable`: проверь токен и что бот вышел из облачного Bot API (`logOut`), затем перезапусти `app` |
| `docker compose up --wait` падает: `app` unhealthy, в `/readyz` `"telegram":"fail"` | один неверный токен делает `app` unhealthy (healthcheck смотрит `/readyz`), остальные боты при этом работают. Исправь токен в `.env` и выполни `docker compose --profile telegram up -d --wait app`. Чтобы поднять стек без шлюза, очисти все четыре `TELEGRAM_*_TOKEN` |
