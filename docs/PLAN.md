# ИИ-команда для фитнес-тренера: план системы агентов

> 13.11.2026 · Источник: [Claude Doc, вкладка «План»](https://claude.ai/artifact/1nZFDWQHC3GTEtXY6ijnrE). Схемы архитектуры и дорожной карты есть только в документе. Задачи MVP — в [MVP-BACKLOG.md](MVP-BACKLOG.md), текущий статус — в [VERSION-0.1.md](VERSION-0.1.md).

## Цель и принципы

Цель: тренер тратит на соцсети не больше 30–40 минут в день — снимает видео, одобряет и отвечает на нестандартные вопросы. Всё остальное (аналитика, сценарии, тексты, обложки, монтаж, публикация, первичные продажи) делает команда из 7 агентов, с которой тренер общается в Telegram, как с живыми сотрудниками.

Принципы:

- **Человек в контуре на ключевых точках.** Публикация, цены, нестандартные ответы клиентам и любые медицинские темы (травмы, беременность, болезни) идут только через одобрение тренера.
- **Одна база знаний бренда на всех.** Голос, позиционирование, аудитория, продукты, цены, визуальный стиль, запретные темы. Агенты читают её перед каждой задачей — так контент звучит одинаково.
- **Агент = роль + скиллы + инструменты + права.** У каждого есть узкая зона ответственности и чёткий формат результата.
- **Начинаем с малого.** Сначала 3 агента, которые экономят больше всего времени, потом расширяем.
- **Только официальные API и честные методы.** Аккаунт тренера — главный актив, рисковать им ради автоматизации нельзя (подробнее в разделе «Ограничения и риски»).

## Архитектура

Тренер видит только Telegram; под ним оркестратор превращает сообщения в задачи, раздаёт их агентам и возвращает результат на согласование.

```
Тренер ──► Telegram (супергруппа с топиками, боты агентов)
              │
              ▼
        Оркестратор (Go + очередь задач)
              │
   ┌──────────┼──────────────────────────────┐
   ▼          ▼                              ▼
 7 агентов ──► база знаний бренда      внешние сервисы
 (Claude)     (Postgres + pgvector)    (Instagram API, S3, CRM)
```

Все агенты читают одну базу знаний бренда, а к внешним сервисам идут только с теми правами, которые нужны их роли. Публикация и отправка в директ срабатывают только после одобрения тренера (исключение — типовые ответы продажника по утверждённому скрипту).

## Состав команды и скиллы

В команде 7 агентов. Маркетолог — тимлид: распределяет задачи и собирает результат. Остальные работают по его брифам и по прямым запросам тренера.

| Агент | Главный результат | Кто одобряет |
| --- | --- | --- |
| Маркетолог | Стратегия, контент-план на неделю, отчёт по цифрам | Тренер, раз в неделю |
| Разведчик | Еженедельный отчёт по конкурентам и аудитории | Не нужно — внутренний документ |
| Копирайтер | Сценарии, подписи, тексты каруселей и прогревов | Тренер, перед публикацией |
| Дизайнер | Обложки, карусели, шаблоны сторис | Тренер, перед публикацией |
| Монтажёр | Готовый рилс из исходников | Тренер, перед публикацией |
| Продажник | Диалоги в директе до оплаты | Тренер — только нестандартные случаи |
| Технарь | Публикация, интеграции, мониторинг системы | Не нужно — пишет алерты |

### 1. Маркетолог (тимлид)

Отвечает за то, что и зачем публикуем. Получает отчёты разведчика, статистику аккаунта и цели тренера; отдаёт контент-план и брифы остальным.

Скиллы:

- `strategy` — позиционирование, ЦА, рубрикатор (польза / личное / экспертиза / продажа), воронка «рилс → лид-магнит → прогрев → продажа».
- `content-plan` — недельный план: 4–5 рилс, 2–3 карусели, ежедневные сторис, 1 прогрев к запуску продукта.
- `brief` — бриф на единицу контента: цель, аудитория, ключевая мысль, CTA, кодовое слово, референсы.
- `analytics` — разбор Insights (охват, досмотры, сохранения, переходы в директ), выводы «что повторить / что убрать».
- `launch` — план запуска продукта: даты прогрева, лид-магнит, офер, дедлайны.

### 2. Разведчик (конкурентная аналитика)

Разбирает, как устроен контент и воронки конкурентов, и превращает это в идеи для вас. Работает через отдельный рабочий аккаунт (почта, Telegram, Instagram), подписанный на конкурентов из вашего списка.

Скиллы:

- `monitor` — ежедневно фиксирует новые рилс, посты и сторис конкурентов (тема, формат, хук, CTA).
- `transcribe` — транскрибирует публичные видео и подкасты, выделяет хуки, структуру и аргументы.
- `funnel-map` — проходит воронку как обычный подписчик: пишет кодовое слово, получает лид-магнит, подписывается на рассылку. Результат — схема воронки: шаги, офер, цены, сроки, триггеры.
- `warmup-breakdown` — разбирает прогревы в сторис по дням: какие боли поднимали, какие возражения закрывали, когда открыли продажи.
- `audience-voice` — собирает темы из публичных комментариев: вопросы, боли, возражения, слова аудитории. В отчёт идут формулировки и частота, без имён и профилей.
- `report` — еженедельный отчёт: топ-10 тем по вовлечению, удачные форматы, схемы воронок, идеи продуктов, пробелы, которые никто не закрывает.

Границы: разведчик разбирает механику, а не копирует. Чужие видео, тексты и лид-магниты не публикуются от вашего имени даже в переработанном виде — копирайтер пишет своё на основе выводов. Подробнее — в разделе «Ограничения и риски».

### 3. Копирайтер

Пишет все тексты голосом тренера по брифам маркетолога.

Скиллы:

- `brand-voice` — словарь, тон, запретные фразы; перед каждой задачей сверяется с базой бренда.
- `reels-script` — сценарий рилс: хук на 1–3 секунды, раскадровка, текст в кадре, подпись, CTA с кодовым словом.
- `carousel` — текст карусели по слайдам (8–10 слайдов, мысль на слайд).
- `stories-warmup` — сценарии сторис и многодневных прогревов.
- `lead-magnet` — тексты своих лид-магнитов: гайды, чек-листы, мини-курсы.
- `sales-scripts` — скрипты для продажника и автоответы на кодовые слова.
- `fact-check` — сверяет советы по питанию и тренировкам с базой экспертизы тренера, медицинские формулировки помечает на проверку.

### 4. Дизайнер

Делает визуал в рамках брендбука.

Скиллы:

- `brand-kit` — цвета, шрифты, сетки, правила фото; не выходит за брендбук.
- `reels-cover` — обложки рилс, единая сетка профиля.
- `carousel-layout` — вёрстка каруселей по готовым шаблонам.
- `stories-templates` — шаблоны сторис: опросы, отзывы, анонсы, «до/после» (только с согласия клиента).
- `lead-magnet-pdf` — оформление гайдов и чек-листов в PDF.

### 5. Монтажёр

Превращает сырые видео тренера в готовые рилс. Тренер скидывает исходники в Telegram — монтажёр возвращает черновик.

Скиллы:

- `rough-cut` — вырезает паузы, оговорки, дубли по транскрипту.
- `subtitles` — субтитры в фирменном стиле, акценты на ключевых словах.
- `broll-music` — подбирает перебивки из медиатеки тренера и лицензионную музыку.
- `variants` — 2–3 версии с разными хуками для теста.
- `export` — 9:16, 1080×1920, обложка, нарезка в сторис и Shorts.

### 6. Продажник

Ведёт переписку в директе по вашему скрипту: выясняет запрос, предлагает подходящую услугу, отвечает на возражения, отправляет ссылку на оплату. Цены и условия берёт только из прайса в базе знаний.

Скиллы:

- `qualify` — цель, уровень подготовки, ограничения, формат (онлайн / зал), бюджет, сроки.
- `offer-match` — подбирает услугу из прайса и объясняет, почему подходит.
- `objections` — отвечает на «дорого», «нет времени», «не получится» и т. п. по готовым ответам тренера.
- `checkout` — отправляет ссылку на оплату; карты и платёжные данные в чат не принимает.
- `handoff` — передаёт диалог тренеру в Telegram с кратким резюме, если: вопрос о здоровье, травмах, беременности; скидка или нестандартные условия; негатив или жалоба; агент не уверен.
- `crm-log` — записывает лид, этап, итог и причину отказа в CRM.

### 7. Технарь

Держит систему в рабочем состоянии.

Скиллы:

- `publish` — публикация и расписание через официальный Instagram API.
- `integrations` — Telegram, Instagram, CRM, платёжка, хранилище медиа.
- `monitoring` — ошибки, лимиты API, расход токенов и денег; алерты в Telegram.
- `access` — токены и доступы, обновление ключей, бэкапы базы знаний.
- `onboarding-agent` — добавление нового агента или скилла по шаблону.

## Интеграция с Telegram

Команда живёт в одной супергруппе с топиками: у каждого агента свой бот с именем и аватаром, а тренер пишет им, как сотрудникам. С мая 2026 года в Telegram есть режим Bot-to-Bot: боты видят сообщения друг друга в группе, его включают в @BotFather ([документация](https://core.telegram.org/api/bots/bot-to-bot)). Но реальная передача задач идёт через оркестратор и очередь, а Telegram — только интерфейс: так проще избежать бесконечных переписок ботов и потери задач.

Топики группы:

| Топик | Кто пишет | Что происходит |
| --- | --- | --- |
| Планёрка | Маркетолог, тренер | Контент-план на неделю, недельный отчёт, приоритеты |
| Разведка | Разведчик | Находки за день, отчёт по пятницам |
| Исходники | Тренер | Сырые видео и фото, голосовые с идеями |
| Продакшн | Копирайтер, дизайнер, монтажёр | Черновики с кнопками «Одобрить / Правки / Отклонить» |
| Директ | Продажник | Эскалации с резюме диалога, итоги дня по лидам |
| Техничка | Технарь | Алерты, расходы, статус публикаций |

Как тренер общается с командой:

- Обычным текстом или голосом с упоминанием: «@копирайтер, сделай сценарий про присед для новичков». Голосовые транскрибируются.
- Без упоминания задачу забирает маркетолог и сам распределяет.
- Команды: `/plan` — план на неделю, `/idea` — бросить идею в бэклог, `/status` — что в работе, `/report` — цифры за неделю, `/pause` — остановить публикации и автоответы.
- Правки реплаем на черновик. Каждая правка сохраняется в базу знаний как пример «как не надо / как надо» — агенты учатся на них.
- Доступ только из белого списка Telegram ID: боты игнорируют чужих и не работают в других чатах.

## Технический стек

Ядро — оркестратор на Go с очередью задач и LLM с вызовом инструментов; для быстрого MVP можно собрать первые сценарии в n8n и перенести в код, когда стабилизируются.

| Слой | Вариант | Зачем |
| --- | --- | --- |
| Мозг агентов | Claude API (tool use) или Claude Agent SDK | Тексты, анализ, диалоги; скиллы как папки с SKILL.md |
| Оркестратор | Go-сервис + Redis-очередь | Роутинг задач, статусы, ретраи, защита от циклов |
| База знаний | PostgreSQL + pgvector | Бренд, прайс, скрипты, архив контента, правки тренера |
| Медиа | S3-совместимое хранилище | Исходники, готовые рилс, обложки |
| Видео | Whisper (транскрипция) + ffmpeg / Remotion | Автонарезка, субтитры, экспорт |
| Дизайн | HTML/SVG-шаблоны или Figma/Canva API + генерация изображений | Карусели и обложки строго по брендбуку |
| Instagram | Официальный Instagram Graph API (Publishing, Insights, Comments, Messaging) | Публикация, статистика, директ без риска бана |
| Telegram | Bot API, 7 ботов + супергруппа с топиками | Интерфейс команды |
| CRM | Таблица в Postgres или Buildin.ai | Лиды, этапы, причины отказов |
| Инфраструктура | Docker Compose на VPS вне РФ + GitLab CI | Instagram и часть AI-API недоступны из РФ-инфраструктуры |

Каждый скилл — папка с инструкцией (SKILL.md), примерами хороших работ и чек-листом самопроверки. Агент = системный промпт роли + набор скиллов + список разрешённых инструментов; продажник, например, не имеет доступа к публикации, а дизайнер — к директу.

## Ограничения и риски

Главный риск — потеря аккаунта тренера или репутации, поэтому автоматизация идёт только через официальные каналы.

**Директ Instagram.** Продажник работает через официальный Messaging API (нужен профессиональный аккаунт). Правила, которые заложены в систему:

- Писать можно только в ответ: когда человек пишет в директ, отвечает на сторис или комментирует пост, открывается 24-часовое окно. Холодные рассылки и авто-DM новым подписчикам недоступны.
- На комментарий можно ответить одним личным сообщением в течение 7 дней, дальше — только если человек ответил. Поэтому первое сообщение на кодовое слово заканчивается вопросом, а не просто ссылкой.
- После 24 часов отвечает только тренер вручную: тег Human Agent даёт до 7 дней, но он предназначен только для сообщений живого человека, а попытка автоматизировать его возвращает ошибку API. Эскалации в Telegram должны приходить с таймером до закрытия окна.
- Meta требует предупреждать собеседника, что отвечает автоматический помощник, и давать выход на человека ([документация Meta](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login/messaging-api)). Да и клиенты ценят честность: «я ассистент Анастасии, помогу подобрать формат».

**Аккаунт тренера.** Никаких неофициальных ботов, которые входят по логину и паролю, масслайкинга и массфолловинга: за это Instagram режет охваты и банит.

**Разведка.** Изучать публичный контент конкурентов и проходить их воронки как подписчик — нормальная практика маркетинга. Но часть исходной задумки создаёт реальные риски, поэтому в плане она заменена:

| Было в идее | Риск | Что делаем вместо |
| --- | --- | --- |
| «Воровать» контент, прогревы, лид-магниты | Авторское право, жалобы и удаление постов, репутация «копирует у коллег» | Разбираем структуру и механику, пишем своё |
| Выгрузить все комментарии и чаты аудитории | Персональные данные чужих людей, запрет скрапинга в правилах Meta | Собираем темы и формулировки без имён, в умеренном объёме |
| Заходить в закрытые и платные чаты и выгружать их | Нарушение условий доступа и приватности участников | Только открытые каналы и чаты; купленный продукт разбираем для себя, не распространяем |
| Фейковая личность, много аккаунтов | Баны, связка с вашим брендом при вскрытии | Один рабочий аккаунт, без выдачи себя за реального человека |

**Экспертность.** Неверный совет по тренировкам или питанию бьёт по репутации сильнее любого бана. Всё публичное проходит через тренера, продажник не даёт персональных рекомендаций по здоровью.

**Данные клиентов.** Переписки и анкеты — персональные данные. Храним минимум, доступ по ролям; статус сервера и требования локализации данных стоит сверить с юристом перед запуском продажника.

## Дорожная карта

Запускаем сначала то, что экономит больше всего времени и не трогает клиентов напрямую; продажник включается, когда база знаний и скрипты уже обкатаны. Схема из 5 этапов и 4 гейтов есть в исходном документе; детальные задачи первого этапа — в [MVP-BACKLOG.md](MVP-BACKLOG.md).

Сроки — оценка для одного разработчика в свободное время. Разведчика можно запустить раньше в упрощённом виде (разбор ссылок, которые тренер кидает в чат), если идеи для контента нужны уже на первом этапе.

## Метрики и следующие шаги

Система работает, если тренер тратит меньше времени, а контент и продажи не проседают. Целевые значения — ориентиры, уточним после замера текущего уровня.

| Метрика | Как считаем | Ориентир |
| --- | --- | --- |
| Время тренера на соцсети | Самооценка + время до одобрения в Telegram | ≤ 40 минут в день |
| Регулярность | Публикации по плану / всего запланировано | ≥ 90% |
| Одобрение с первого раза | Черновики без правок / все черновики | ≥ 70% через 2 месяца |
| Вовлечение | Сохранения, пересылки, досмотры рилс (Insights) | Рост к среднему до запуска |
