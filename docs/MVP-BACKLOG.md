# MVP: бэклог задач

> Статусы на 24.11.2026 · Источник: [Claude Doc, вкладка «MVP: бэклог задач»](https://claude.ai/artifact/1nZFDWQHC3GTEtXY6ijnrE). Актуальные статусы ведутся там; этот файл — снимок.

MVP — Telegram-команда из 4 агентов, которая превращает идею тренера в готовый рилс: сценарий, монтаж, субтитры, обложка и подпись. Публикует тренер вручную. Оценка — 4–5 недель до пилота.

**В MVP:** Маркетолог (план и брифы), Копирайтер (сценарии и подписи), Монтажёр (склейка и субтитры), Дизайнер-лайт (обложки рилс). Технарь — как инфраструктура, без своего бота.

**Не в MVP:** Продажник, Разведчик, автопубликация, дизайн каруселей, B-roll и музыка, аналитика Insights.

## Порядок запуска агентов

1. Волна 1: T1.1 — каркас, один агент. На нём стоит всё остальное. Проверка кода — через GitHub Actions: в облачной среде агентов закрыт Go-прокси, так что локальные `make check` и git-хуки заменены зелёным CI (решение 13 ноября).
2. Волна 2, параллельно: T1.2 Telegram, T1.3 + T1.4 задачи и LLM, T1.5 база знаний, T3.1 транскрипция (отдельный CLI).
3. Волна 3, параллельно: контент T2.1–T2.4 и монтаж T3.2–T3.5.
4. Волна 4: сборка, деплой и пилот T4.1–T4.4.

## План до тестирования у тренера (с 23.11.2026)

Цель — продукт, который можно отдать тренеру на тестирование: идея текстом (можно надиктовать диктовкой телефона) → план и брифы Маркетолога → сценарий и подпись Копирайтера → исходник в «Исходники» → рилс с субтитрами от Монтажёра → обложка от Дизайнера. Сервис работает на VPS, у тренера есть инструкция на одну страницу.

Задачи идут **строго последовательно**, по одной: разработка → ревью отдельным агентом → правки → тестирование → мерж → следующая задача. Так PR не конфликтуют между собой.

«Тестирование» — зелёный CI по всем джобам и, для задач, которые видно в Telegram, живая проверка на Mac Виктора по промпту от ассистента до мержа. По каждому FAIL правки делает тот же агент.

## Как работаем с агентами-разработчиками

- Каждая задача — отдельный агент с брифом: ID, контекст, критерий готовности, ветка вида `feature/t1-2-telegram-gateway` (на `feature/**` CI сам коммитит `go mod tidy`).
- Агент работает в своём git worktree и открывает PR с тестами.
- Отдельный агент-ревьюер проверяет PR по критерию готовности.
- В чат приходит короткий отчёт, мержит Виктор — только после «можно мержить» от ассистента. Статусы ведём в таблицах ниже.
- После каждого мержа остальные PR обновляются на main (CI требует актуальный main); конфликты обычно только в `CHANGELOG.md` и `docs/SETUP.md`.
- Секреты (токены ботов, ключи API) агентам не передаются: они пишут код и `.env.example`, реальные значения Виктор кладёт на сервер сам.
